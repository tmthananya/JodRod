[B] auth.users (1) <----> (0..N) public.cars

    - Foreign key: cars.user_id REFERENCES auth.users(id).
    - Constraint: UNIQUE (user_id, license_plate) prevents duplicate plates per user.
    - Security: Each user can only view, edit, or delete their own cars.

[C] auth.users (1) <----> (0..N) public.parking_spaces
    - One user can register and offer MULTIPLE parking spaces / lots.
    - Foreign key: parking_spaces.owner_id REFERENCES auth.users(id).
    - Legacy Community Spaces: owner_id IS NULL (public discovery only; cannot
      be edited or deleted by arbitrary users).
    - Security: Only the owner (auth.uid() = owner_id) can edit or delete a lot.

[D] public.cars (1) <----> (0..1) public.reservations (Active)
    - One car can have at most ONE active reservation ('pending' or 'confirmed')
      at any given time.
    - Enforced by PostgreSQL Partial Unique Index:
      CREATE UNIQUE INDEX uq_active_reservation_per_car 
      ON public.reservations (car_id) 
      WHERE status IN ('pending', 'confirmed');

[E] public.parking_spaces (1) <----> (0..N) public.reservations
    - A parking lot holds multiple confirmed bookings up to its total capacity.
    - available_spaces tracks open capacity (0 <= available_spaces <= capacity).
    - When available_spaces reaches 0, parking lot status transitions to 'full'.

[F] Cross-User Vehicle Defense (Composite Foreign Key)
    - Problem: User A must NEVER be able to reserve User B's car.
    - Database Enforcement:
      In public.cars:         UNIQUE (id, user_id)
      In public.reservations: FOREIGN KEY (car_id, user_id)

    - If User A attempts to submit User B's car_id, PostgreSQL immediately throws
      a foreign key violation error because (car_B_id, user_A_id) does not exist.
